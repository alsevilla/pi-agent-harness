# Sources and adaptation notes

This skill is an original adaptation for this engineering harness.

Primary reference reviewed:
- Collective Brain, **UX Flow & Wireframer**:
  https://collectivebrain.de/en/skills/ux-flow-wireframer/

Concepts retained in adapted form:
- establish user/goal/success before visual design;
- map entry points and the happy path;
- make branches, errors, abandonment, and recovery explicit;
- use Mermaid plus low-fidelity text wireframes;
- include relevant loading/empty/error/success states;
- audit unnecessary steps/inputs;
- surface open product decisions instead of silently deciding them.

Harness-specific changes:
- read-only by default;
- project authority outranks generic UX heuristics;
- no forced one-CTA rule when the product legitimately requires multiple
  administrative actions;
- no repository artifact without mutation authority;
- explicit handoff to existing frontend capabilities and engineering lifecycle.
